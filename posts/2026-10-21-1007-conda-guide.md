# conda 常用命令：环境与包管理入门及速查

![conda 教程封面（AI 生成插画）](images/2026-10-21-conda-guide-02.jpg)

conda 同时提供环境管理与软件包管理能力。日常使用时，最重要的是先确定操作哪个环境，再安装、更新或删除其中的软件包。

本文采用"入门流程 → 分类说明 → 命令速查"的顺序。主要示例统一使用 `demo-env` 作为环境名。

> 本文根据原文整理，命令未实机测试。软件包是否可用取决于操作系统、处理器架构、频道和依赖条件。封面沿用原文相对路径，发布前请确认文件存在。

## 一、开始前：确认 conda 可用

需要先安装提供 conda 的发行版或工具，例如 Miniconda、Anaconda Distribution 或 Miniforge。

- Windows：可先使用安装程序提供的 Prompt。
- Linux / macOS：使用已完成 conda 初始化的终端。
- PowerShell 等 Shell：激活环境前可能需要初始化。

查看 conda 版本：

```text
conda --version
```

查看安装信息：

```text
conda info
```

查看帮助：

```text
conda --help
conda create --help
```

### 激活环境失败怎么办？

如果提示 Shell 尚未初始化，按当前使用的 Shell 选择一条命令执行。

Bash：

```text
conda init bash
```

Zsh：

```text
conda init zsh
```

PowerShell：

```text
conda init powershell
```

初始化会修改相关 Shell 配置。执行后重新打开终端，再尝试激活环境。

如果连 `conda` 命令都找不到，应先检查安装或使用安装程序提供的 Prompt；`conda init` 本身无法解决命令不可用的问题。

## 二、先完成一次完整操作

下面的流程依次创建环境、激活环境、安装 NumPy、验证安装并退出。

执行前，请确认没有需要保留的同名 `demo-env` 环境。安装过程中可能出现确认提示，先查看变更内容再确认。

```text
conda create -n demo-env python=3.12
conda activate demo-env
python --version
conda install -n demo-env numpy
python -c "import sys; import numpy; print(sys.executable); print(numpy.__version__)"
conda deactivate
```

预期结果：

- 创建名为 `demo-env` 的环境。
- 环境使用求解器选出的 Python 3.12 系列版本。
- 验证命令输出该环境的 Python 路径和 NumPy 版本。

如果创建失败，应根据报错检查频道、网络和版本可用性，不要直接跳过失败步骤。

后文代码块主要用于独立查阅，不需要整篇从头执行到尾。

## 三、环境管理

### 1. 查看环境

```text
conda env list
```

列表中的 `*` 表示当前激活环境。环境的实际位置也显示在列表中，不一定都在安装目录下的 `envs/`。

下面的命令也可以查看环境：

```text
conda info --envs
```

### 2. 创建环境

创建环境并指定 Python：

```text
conda create -n demo-env python=3.12
```

也可以在创建时一起安装主要依赖：

```text
conda create -n demo-env python=3.12 numpy pandas
```

以上是两种备选方式，不要对同一个已存在的环境重复创建。

参数说明：

| 参数 | 含义 |
|---|---|
| `-n` / `--name` | 指定环境名称 |
| `python=3.12` | 请求 Python 3.12 系列 |
| `numpy pandas` | 同时请求安装的软件包 |

把主要依赖放在同一次创建操作中，有助于求解器一起考虑它们的兼容性。

### 3. 激活与退出

```text
conda activate demo-env
```

检查当前 Python 路径：

```text
python -c "import sys; print(sys.executable)"
```

退出当前激活层级：

```text
conda deactivate
```

退出后可能回到 `base`、上一个环境或没有 conda 环境的状态，取决于此前的激活方式。

### 4. 不激活也能运行程序

```text
conda run -n demo-env python --version
```

适合明确指定运行环境，也适合脚本和自动化任务。

### 5. 克隆环境

以下命令要求 `demo-env` 已存在，且 `demo-copy` 尚不存在：

```text
conda create -n demo-copy --clone demo-env
```

克隆适合在当前系统上建立副本，不应作为跨平台迁移方法。

### 6. 删除环境

先退出准备删除的环境，再删除：

```text
conda deactivate
```

```text
conda env remove -n demo-copy
```

删除前检查环境名。该操作会移除目标环境及其中的软件包，环境目录中自行保存的文件也可能受到影响。项目源码和数据应放在环境目录之外。

## 四、软件包管理

可以先激活环境再管理包，也可以用 `-n` 明确指定目标环境。本文主要采用后者。

### 1. 查看已安装的包

```text
conda list -n demo-env
```

按名称筛选：

```text
conda list -n demo-env numpy
```

精确匹配名称：

```text
conda list -n demo-env "^numpy$"
```

`conda list` 的筛选参数采用正则表达式，不是文件名通配符。

例如，`numpy*` 并不表示通常理解的"numpy 后接任意字符"，而且未加引号时还可能被 Shell 展开。

### 2. 搜索可安装的包

```text
conda search numpy
```

查看当前配置频道中可用的 Python 3.12 系列：

```text
conda search "python=3.12"
```

搜索结果取决于频道与平台，不代表每个版本都能与当前环境的其他依赖同时安装。

### 3. 安装包

```text
conda install -n demo-env numpy pandas
```

指定版本系列：

```text
conda install -n demo-env "numpy=1.26"
```

指定版本可能导致其他依赖变化，或因不兼容而失败。先查看求解结果再确认。

预览安装变更：

```text
conda install -n demo-env pandas --dry-run
```

`--dry-run` 不执行实际安装，但仍可能访问网络、读取或更新索引缓存。

### 4. 更新包

更新单个包：

```text
conda update -n demo-env numpy
```

更新环境中的所有 conda 包：

```text
conda update -n demo-env --all
```

"更新"受频道、依赖和固定版本条件约束，不保证安装上游最新版本。

已有稳定项目在批量更新前，建议先导出环境，或克隆一份用于验证。

### 5. 删除包

```text
conda remove -n demo-env pandas
```

删除包可能连带删除依赖它的其他包，应先查看拟议变更。

`uninstall` 是 `remove` 的别名，本文统一使用 `remove`。

## 五、Python 版本管理

对于不同 Python 版本，优先创建独立环境。例如，下面创建另一个使用 Python 3.13 的环境：

```text
conda create -n py313-env python=3.13
```

如果确实需要修改已有环境：

```text
conda install -n demo-env python=3.12
```

该操作会重新求解依赖，可能更新、降级或移除其他包。

更新环境中的 Python：

```text
conda update -n demo-env python
```

这不保证跨越到最新大版本或次版本。最终版本取决于环境约束和可用软件包。

验证实际版本：

```text
conda run -n demo-env python --version
```

## 六、导出、共享与恢复环境

不同导出方式保留的信息不同，应根据用途选择。

| 导出方式 | 适用场景 | 主要限制 |
|---|---|---|
| 完整 YAML | 记录当前环境，供备份和恢复参考 | 可能包含平台相关依赖、构建信息和路径 |
| `--from-history` YAML | 分享主要依赖，便于在其他平台重新求解 | 不完整记录间接依赖和 pip 安装内容 |
| 显式清单 | 同平台或兼容子平台恢复精确 conda 包构建 | 不包含 pip 包，依赖包地址仍可访问 |

以下重定向使用 `>`，会覆盖当前目录下的同名文件。

### 1. 导出完整 YAML

```text
conda env export -n demo-env > environment.yml
```

恢复为另一个环境：

```text
conda env create -n demo-restored -f environment.yml
```

分享前应检查文件：

- `prefix:` 可能包含本机路径，分享时通常应删除。
- 某些依赖或构建只适用于原平台。
- 文件可能含本机路径或私有频道地址。
- 即使记录了版本，未来也可能因软件包下架或网络问题无法恢复。

因此，完整 YAML 不能保证在任何机器上原样复现。

### 2. 导出主动安装的主要规格

```text
conda env export -n demo-env --from-history > environment-history.yml
```

恢复：

```text
conda env create -n demo-portable -f environment-history.yml
```

这种方式主要保留显式请求的 conda 规格，让目标平台重新求解依赖，通常更适合跨平台分享。

它不保证得到相同的间接依赖版本，也不会完整记录 pip 安装的软件包。

### 3. 导出显式包清单

```text
conda list -n demo-env --explicit > explicit-spec.txt
```

在相同平台或兼容子平台恢复：

```text
conda create -n demo-explicit --file explicit-spec.txt
```

显式清单记录具体 conda 包地址，不包括 pip 包，也不应直接拿来跨操作系统恢复。

### 4. 根据 YAML 更新已有环境

```text
conda env update -n demo-env -f environment.yml
```

如需删除文件中不再需要的 conda 依赖，可考虑：

```text
conda env update -n demo-env -f environment.yml --prune
```

`--prune` 可能删除软件包，不能把它当成普通追加安装；也不要依靠它完整清理 pip 安装内容。

## 七、conda 与 pip 怎么配合？

conda 和 pip 有不同的管理范围。

| 对比项 | conda | pip |
|---|---|---|
| 主要用途 | 管理环境及多种语言的软件包 | 安装 Python 软件包 |
| 创建环境 | 支持 | 本身不负责；Python 可使用标准库 `venv` |
| 包来源 | 配置的 conda 频道 | PyPI、其他索引、本地文件等 |
| 分发形式 | conda 包，通常按平台构建 | wheel 或源码分发 |
| 依赖处理 | 求解 conda 包元数据中的依赖 | 解析 Python 包声明的依赖 |

现代 pip 具备依赖解析能力。wheel 也可能包含编译组件或部分本地库；但 pip 和 conda 无法完全理解彼此管理的所有状态。

### 推荐的混用顺序

1. 创建独立项目环境。
2. 先安装能够通过 conda 获得的依赖。
3. 为该环境安装 pip。
4. 使用该环境的 `python -m pip` 安装剩余包。

为示例环境安装 pip：

```text
conda install -n demo-env pip
```

下面演示通过该环境的 pip 安装 `rich`。这是 pip 用法示例，不表示该包只能通过 pip 获取：

```text
conda run -n demo-env python -m pip install rich
```

检查 pip 路径与依赖：

```text
conda run -n demo-env python -m pip --version
conda run -n demo-env python -m pip check
```

`pip check` 只检查它能识别的 Python 依赖关系，不能验证整个 conda 环境的二进制兼容性。

### 混用时注意

- 不要使用 `sudo pip install` 向 conda 环境安装包。
- 尽量避免对同一个包交替使用 conda 和 pip 管理。
- pip 安装后再大幅修改 conda 依赖，可能破坏已有兼容关系。
- 混合环境难以维护时，按整理后的依赖清单重新创建环境通常更可靠。

`conda list` 中，pip 安装的包常显示 `pypi` 频道或 `pypi_0` 构建标记。这是常见线索，不能保证准确识别所有安装方式。

## 八、频道与镜像

频道是 conda 查找软件包的位置；镜像是某个频道内容的另一个访问入口。

### 1. 先查看现有配置

```text
conda config --show-sources
conda config --show channels
conda config --show channel_priority
```

`--show-sources` 可以帮助定位配置来自哪些文件。配置可能存在于多个层级，不一定只有用户目录下的 `.condarc`。

分享配置输出前，应检查是否含访问令牌、私有地址或个人路径。

### 2. 临时指定频道

下面从 `conda-forge` 创建一个独立环境：

```text
conda create -n forge-demo --override-channels -c conda-forge python=3.12 numpy
```

这里的频道名是 `conda-forge`，不是 `conda_forge`。

- `-c conda-forge`：为本次操作添加该频道。
- `--override-channels`：忽略通常配置的频道，只使用本次指定的频道。

只使用 `-c` 时，其他已配置频道仍可能参与求解。

对于长期项目，尽量保持频道策略一致，避免无计划地混用不同频道的二进制包。

### 3. 严格频道优先级

```text
conda config --set channel_priority strict
```

严格优先级可减少低优先级频道中同名包参与求解的情况，有助于保持依赖来源一致，但不能保证解决所有兼容问题。

该命令会修改配置。修改前先记录原值；需要撤销时，恢复之前的值。

### 4. 使用镜像站

镜像速度取决于网络、同步状态和软件包覆盖情况，不一定始终更快。

推荐步骤：

1. 查看镜像站当前官方说明，确认支持的频道和平台。
2. 记录原配置，并备份实际需要修改的配置文件。
3. 选择一套镜像方案，避免连续叠加多家镜像。
4. 修改后先搜索软件包，或在新环境中验证。

不默认添加历史 `pkgs/free` 频道，也不把多年以前的镜像地址列表当成当前配置方案。

本文未在线核验镜像服务状态，因此不提供声称已验证可用的镜像地址。

### 5. 撤销配置时注意

删除用户级配置中的 `channels` 项：

```text
conda config --remove-key channels
```

这只影响相应配置文件中的该项。如果该项不存在，命令可能报错。

它不等于将所有 conda 配置恢复出厂设置：其他配置文件、`default_channels`、`custom_channels` 等仍可能生效。撤销后应重新查看：

```text
conda config --show-sources
conda config --show channels
```

恢复此前备份的配置，通常比盲目删除配置项更准确。

## 九、管理 conda 自身与清理缓存

### 1. 更新 conda

对于常见的、由 base 环境管理 conda 的安装方式：

```text
conda update -n base conda
```

更新前查看变更。如果 conda 由系统包管理器或其他工具维护，应遵循对应安装方式的更新说明。

Anaconda Distribution、Miniconda 和 Miniforge 不是同一个产品。更新 Anaconda 元包不是所有 conda 用户都需要执行的步骤。

### 2. 理解缓存与安装位置

conda 通常会保留下载文件和解压后的包缓存，以便后续安装复用。

包缓存不是项目环境的实际安装目录。环境中的文件可能通过硬链接、复制或其他方式从缓存建立，具体取决于配置和文件系统。

查看环境位置：

```text
conda env list
```

查看缓存等安装信息：

```text
conda info
```

### 3. 先预览缓存清理

```text
conda clean --all --dry-run
```

确认后再执行：

```text
conda clean --all
```

常用选项：

| 选项 | 用途 |
|---|---|
| `--packages` / `-p` | 清理未使用的包缓存 |
| `--tarballs` / `-t` | 清理下载的包归档 |
| `--all` | 清理多类可清理缓存 |
| `--dry-run` | 预览操作 |
| `--help` | 查看当前版本支持的选项 |

清理缓存通常不会卸载环境中的包，但后续安装可能需要重新下载。

部分符号链接配置会使缓存清理影响已有环境，应根据安装方式核对。不要把手动删除整个缓存目录或 `--force-pkgs-dirs` 当成常规清理办法。

`always_yes` 只影响自动确认行为，与减少缓存占用没有直接关系。

## 十、常见问题

### 为什么包安装了，Python 仍然找不到？

先确认运行的是哪个解释器：

```text
conda run -n demo-env python -c "import sys; print(sys.executable)"
```

再查看目标环境中的包：

```text
conda list -n demo-env
```

如果在编辑器或 Notebook 中运行，还要确认选择了相同环境的解释器或内核。

### 为什么找不到包？

检查：

- 包名是否正确；
- 指定版本是否存在；
- 当前平台是否有对应构建；
- 配置的频道是否提供该包；
- 频道或镜像是否可以访问。

先用 `conda search` 搜索，再决定是否更改版本、频道或安装方式。

### 为什么依赖求解失败？

通常表示版本条件无法同时满足。

可以先在新环境中只安装 Python 和主要依赖，再逐步加入其他包。不要仅为了完成安装而盲目忽略依赖或强制覆盖文件。

### 如何关闭终端启动时自动进入 base？

许多版本支持：

```text
conda config --set auto_activate_base false
```

配置键名称可能随版本演进。若当前版本不接受该项，先查看本机说明：

```text
conda config --describe
```

关闭自动激活不会删除 base，也不会阻止手动激活环境。

## 十一、常用命令速查

以下包管理命令假定 `demo-env` 已存在。

| 目的 | 命令 |
|---|---|
| 查看版本 | `conda --version` |
| 查看安装信息 | `conda info` |
| 查看配置来源 | `conda config --show-sources` |
| 查看环境 | `conda env list` |
| 创建环境 | `conda create -n demo-env python=3.12` |
| 激活环境 | `conda activate demo-env` |
| 退出当前层级 | `conda deactivate` |
| 不激活运行 | `conda run -n demo-env python --version` |
| 克隆环境 | `conda create -n demo-copy --clone demo-env` |
| 删除副本环境 | `conda env remove -n demo-copy` |
| 查看包 | `conda list -n demo-env` |
| 精确查询已安装包 | `conda list -n demo-env "^numpy$"` |
| 搜索可安装包 | `conda search numpy` |
| 安装包 | `conda install -n demo-env numpy` |
| 更新包 | `conda update -n demo-env numpy` |
| 删除包 | `conda remove -n demo-env pandas` |
| 导出完整 YAML | `conda env export -n demo-env > environment.yml` |
| 导出主要规格 | `conda env export -n demo-env --from-history > environment-history.yml` |
| 从 YAML 创建环境 | `conda env create -n demo-restored -f environment.yml` |
| 更新 conda | `conda update -n base conda` |
